# Commerce, Recommendation and Dashboard Gates

## 1. Purpose

Tài liệu này biến các playbook domain thành **gates có thể kiểm tra** trong từng change. Nó không thay thế code review, security review, legal review, App Review hoặc provider certification. Mỗi change phải chọn profile từ scope thực tế; không copy toàn bộ tài liệu vào context của AI Agent.

## 2. Profile activation matrix

| Feature signal | Required profile | Required artifacts | Minimum risk |
|---|---|---|---|
| Catalog, cart, checkout, order, refund, inventory, seller, payout | Commerce | `COMMERCE_FLOW_SPEC`, `TRANSACTION_CONCURRENCY_TEST` | HighRisk |
| Payment, payout, ledger, entitlement, webhook or external side effect | Commerce + Transaction | Commerce flow + concurrency test + reconciliation evidence | HighRisk |
| Marketplace or multi-seller | Commerce + Compliance | Commerce flow + `COMPLIANCE_SCOPE_RECORD` | HighRisk |
| Search, ranking, recommendations, personalization, feed ordering | Recommendation | `RECOMMENDATION_FEATURE_SPEC` | HighRisk when personalized/high-impact; Normal otherwise only with owner approval |
| KPI, reporting, admin dashboard, analytics export | Dashboard | `DASHBOARD_ANALYTICS_SPEC` | Normal, HighRisk if sensitive/high-impact/export |
| Any race-prone mutation, stock/seat/quota claim, idempotency, retry, queue or webhook | Transaction | `TRANSACTION_CONCURRENCY_TEST` | HighRisk |
| Vietnam launch or Vietnamese users/data/operator | Vietnam compliance | `COMPLIANCE_SCOPE_RECORD` + `VIETNAM_WEB_APP_COMPLIANCE_PROFILE` review | Legal review required |
| iOS/iPadOS client or App Store distribution | Apple iOS | `APPLE_IOS_RELEASE_REVIEW` + Apple profile review | Release review required |
| Digital goods/subscriptions in iOS | Apple iOS + Commerce + Transaction | iOS review + commerce flow + concurrency/reconciliation test | HighRisk |
| Repo/CI/build/dependency/release changes | Repository/CI | `REPOSITORY_CI_PATTERNS_PLAYBOOK` review + CI evidence | Normal/HighRisk by blast radius |

## 3. Required artifacts and naming

Artifacts live under the per-change workspace generated by `new-change.ps1`. The project may use a different path only when the change README records the location and the validator can resolve it.

| Profile | Exact artifact | Must answer |
|---|---|---|
| Commerce | `commerce-flow-spec.md` | state, money, inventory, payment, refund, seller/payout, reconciliation |
| Recommendation | `recommendation-feature-spec.md` | events, candidates, ranking, cold start, metrics, privacy, safety, rollback |
| Dashboard | `dashboard-analytics-spec.md` | grain, metric dictionary, access, freshness, query/performance, export |
| Transaction | `transaction-concurrency-test.md` | invariants, isolation/locking, idempotency, races, recovery, evidence |
| Vietnam compliance | `compliance-scope-record.md` | market, entity, data, vendors, applicable sources, legal owner/status |
| Apple iOS | `apple-ios-release-review.md` | review access, StoreKit, deletion, privacy/SDK, permissions, quality |

Template source is under `workflow/standards/templates/`. A generated artifact is not complete when it still contains unresolved placeholders for an applicable control.

## 4. Hard blockers

The following conditions are `BLOCKED` unless an approved, time-bounded waiver exists. A waiver never suppresses a legal or platform review requirement; it records why release is deferred or why an owner accepts a residual engineering risk.

| Condition | Result |
|---|---|
| Payment/payout/entitlement mutates state without idempotency and duplicate/out-of-order tests | BLOCKED |
| Inventory/seat/quota claim has no invariant and concurrency evidence | BLOCKED |
| Refund/reconciliation path is unspecified or cannot identify unmatched money | BLOCKED |
| Marketplace has no seller/platform role, dispute and moderation ownership | BLOCKED |
| Personalized recommendation has no event consent/privacy scope, cold-start fallback or kill switch | BLOCKED |
| Search/ranking exposes unauthorized, unavailable or unsafe content | BLOCKED |
| Dashboard exposes cross-tenant/sensitive data or export without access tests | BLOCKED |
| Dashboard metric has no definition/grain/timezone/owner | BLOCKED |
| Vietnam scope is applicable but `COMPLIANCE_SCOPE_RECORD` is missing or status is not `LEGAL_REVIEW_REQUIRED`/approved owner decision | NEEDS_LEGAL_REVIEW |
| iOS submission has no review account/backend access, account deletion path or privacy/SDK inventory | BLOCKED |
| iOS digital purchase uses an unreviewed payment route or entitlement trusts client-only state | BLOCKED |
| Evidence claims legal compliance or App Review approval without qualified owner decision | BLOCKED |

## 5. Gate sequence

| Gate | Check | Output |
|---|---|---|
| Scope | Signals, profiles, tier, owners and out-of-scope decisions recorded | `SCOPE_READY` or `SCOPE_BLOCKED` |
| Contract | Domain/API/event/metric/data contracts are versioned | `CONTRACT_READY` or `CONTRACT_BLOCKED` |
| Invariant | State transitions, money, access and concurrency invariants have tests | `INVARIANT_READY` or `INVARIANT_BLOCKED` |
| Privacy/security | Data flow, authorization, abuse, retention and incident controls reviewed | `SECURITY_READY` or `SECURITY_BLOCKED` |
| Operations | SLI/SLO, freshness, reconciliation, alert, rollback and runbook exist | `OPS_READY` or `OPS_BLOCKED` |
| Platform/legal | Vietnam and/or Apple profile is reviewed where activated | `REVIEW_READY` or `NEEDS_LEGAL_REVIEW` |
| Release evidence | CI/test/eval/screenshots/logs/approvals linked to change | `RELEASE_READY` or `RELEASE_BLOCKED` |

## 6. Waiver policy

Waiver records must include condition, risk, affected users/data/money, compensating control, owner, approver, expiry, rollback trigger and follow-up issue. “Will fix later”, “not reproducible”, “works in UI” and “provider handles it” are not sufficient waiver rationales.

A waiver for a Normal engineering check may be approved by the designated engineering owner. A HighRisk waiver requires the domain owner plus security/SRE or finance/privacy owner as relevant. A Vietnam legal question remains `NEEDS_LEGAL_REVIEW` until the qualified reviewer records a decision. An Apple policy question remains platform-review pending until the submission owner verifies the current guideline and evidence.

## 7. Validator contract

The validator may check file existence, non-empty content, naming, selected profiles, JSON/PowerShell syntax, required headings and linked evidence. It must not claim to prove legal compliance, Apple approval, semantic OpenAPI correctness, model fairness, metric correctness or payment-provider certification. Those require human/domain review and executable tests.

## 8. Release decision

```text
PASS
  all activated gates pass; no open blocker; approvals/evidence linked
CONDITIONAL
  only documented, approved, unexpired engineering waivers remain
NEEDS_LEGAL_REVIEW
  applicable legal/platform decision is unresolved
BLOCKED
  hard blocker, missing critical evidence, or expired waiver
```

The release record must state which profiles were activated, which files were reviewed, which checks actually ran, what remains unverified and who made the final decision.
